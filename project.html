One brief. Your name on it.

This is not a worksheet. You will design and build a complete site of your own, put it at a real address, and explain the decisions behind it. A portfolio, a business, a guide, a tool — the subject is yours.

03 The working sequence

From blank page to live address.

A sensible order to work in. Move backward when you discover the content does not fit the design — that is not failure, it is the process.

  1. 01One sentence

    Frame

    State who the site is for, what it does, and why you are the person to make it. If you cannot fit it in a sentence, narrow it.

  2. 02A sitemap

    Map

    List the pages and the content each one owns. Draw the navigation before you write the CSS. Five boxes on paper are enough.

  3. 03Content in HTML

    Mark up

    Write the real content first, in elements that describe it. Get the structure and headings right before decoration.

  4. 04Phone first

    Shape

    Build the small layout first, then let it grow. Use the browser at 360 pixels. Add complexity only when the content asks for it.

  5. 05One good interaction

    Move

    Add the JavaScript your site genuinely needs. Test keyboard access, error states, and the path where the user does everything wrong.

  6. 06Live URL + history

    Ship

    Commit often, deploy, test the live copy on a real phone, and fix what breaks. Then write down what you would do next.

04 Before you call it done

A working site is the starting line.

Use the same four questions a reviewer will: does it mean something, is it well made, does it work in public, and can you defend it?

01 / MEANING

Does it answer the brief?

Specific content, a clear point of view, sensible pages, and navigation that helps rather than decorates.

02 / CRAFT

Is it made well?

Semantic HTML, a coherent visual system, a layout that bends, and interactions that include everyone.

03 / EVIDENCE

Does it work in public?

A live URL, a real Git history, no broken paths, and a phone test that is not just the browser's device mode.

04 / JUDGMENT

Can you defend it?

You can explain what you built, what you borrowed, what AI contributed, and how you checked that it was right.

05 The final conversation

You should be able to defend it.

Not every decision needs a theory. But you should know why the site looks and works the way it does — and where it is still fragile.

  1. Walk me through a decision you changed your mind about.
  2. What did you cut, and why was that the right cut?
  3. Where is this site most likely to break?
  4. Point to something AI helped with. How did you verify it?

06 Practical questions

The things people ask first.

A few honest answers. The short version: choose a real subject, keep the scope small, and build in public from the first week.

Do I need to use a framework?

No. The brief is deliberately built on HTML, CSS, and JavaScript fundamentals. If you choose to add a library, you need to be able to explain what it is doing for you and what it costs.

Can I use images, typefaces, or content from elsewhere?

Your own words and point of view are required. Use images and fonts you have the right to use, and credit them. Borrowing a layout idea is normal; presenting someone else's work as your own is not.

What counts as an interactive element?

A filter, a calculator, a form with real validation, a gallery with keyboard controls, a saved checklist, a theme switch. It should do something useful, make sense without a mouse, and handle the case where the user gets it wrong.

Do I need a server or a database?

No. Neither is required. A static site deployed to a host is enough to meet the brief. If you want to experiment beyond it, that is your choice, not a requirement.

How much Git history is enough?

Enough that the development is visible: a first scaffold, then small commits as pages, styles, and features arrive. One commit called “final” does not show the work; a readable history does.

Can I use AI tools?

Yes — but you own what you submit. Use AI to explore, draft, and debug; then verify it, adapt it, and be ready to explain every line you keep. The course is designed to make you the reviewer, not the relay.

What if I am stuck for an idea?

Start with the idea bank above. Pick a subject you can explain without research, then narrow it until four pages feel natural. A small, complete site beats an ambitious, unfinished one.
