01 Learning outcomes

More than a working page. A way of thinking.

Seven things you will be able to do by the end — each one tied to something you have made, shipped, or reviewed yourself.

  1. 01Systems

    Trace a page through every layer

    Explain how the web delivers a page — from address, through DNS and a server, to rendered pixels — and say which layer owns which part of the result.

  2. 02HTML

    Write markup that means something

    Read and write HTML that describes what content is, not only how it looks, with accessible, semantically correct structure.

  3. 03CSS

    Lay out for any screen

    Style and lay out pages with CSS — the box model, Flexbox, Grid, and responsive design — for a phone and a desktop.

  4. 04JavaScript

    Add behaviour, not chaos

    Use JavaScript to work with the DOM, events, and state, and make interactions that remain understandable when things change.

  5. 05Publishing

    Put it live

    Use version control, deploy to a real address, and diagnose faults across layers instead of guessing at the symptom.

  6. 06Judgment

    Judge code you did not write

    Review code from humans and AI tools for correctness, accessibility, security, and fit — the central skill of the course.

  7. 07Studio

    Build and defend a site of your own.

    Plan, build, deliver, and defend a complete website of your own design — four pages minimum, live at a real address, with the Git history to prove how it got there.

Seven outcomes. One cumulative project.

03 The project

A website only you could make.

A portfolio, a small business, a field guide, a tool, a site about something you know well. The subject is yours. The standards are not negotiable.

  • Four pages or more
  • Your own content
  • Semantic & accessible
  • Responsive on a phone
  • At least one interaction
  • Live at a real address
  • A Git history of the work
  • No server required

04 The central skill

The code runs. That's not the bar.

AI can produce plausible code faster than anyone can read it. This course makes you the reviewer: trace assumptions, test the edges, and ask what the output leaves out.

  • Correctness before cleverness
  • Accessibility is part of done
  • Every input is a trust boundary
  • If you can't explain it, don't ship it
Enter the code review studio

// AI: "Simple and safe!"
const name = new URLSearchParams(location.search).get("name");
const el = document.querySelector("#greeting");

el.innerHTML = `Hello, ${name}`;

Plausible. Not safe. The name comes from the URL, so a visitor controls what lands inside innerHTML. One review question changes the outcome.
