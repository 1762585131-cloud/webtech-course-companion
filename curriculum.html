Course modules

  1. 01 Foundations

    M01 / The system

    Web fundamentals

    Start with the machine, not the syntax. Follow one request from the address bar to the pixels, and learn to use the browser's own tools to see what is really happening.

    • Client–server model
    • URLs
    • DNS
    • HTTP & status codes
    • Browsers & DevTools
    • Web standards
    What this module unlocks

    Learning outcome. Explain how the web delivers a page — from address, through DNS and a server, to rendered pixels — and say which layer is responsible for which part of the result.

    Key question. What actually happens in the seconds after you press Enter?

    Studio exercise

    Follow one real URL through all four layers. For each layer, name a tool you would reach for when it fails.

  2. 02 HTML

    M02 / Structure & meaning

    HTML

    Learn HTML as a description of meaning. Build documents that make sense to a screen reader, a search engine, and the next developer — before you add a single style.

    • Document structure
    • Semantics
    • Text & links
    • Images
    • Tables
    • Forms & validation
    • Accessibility
    What this module unlocks

    Learning outcome. Write and read HTML that describes what content is, not only how it looks, including accessible and semantically correct markup.

    Key question. If the CSS disappears, does the page still make sense?

    Studio exercise

    Mark up a complete page using elements that say what the content is. Then navigate it with a keyboard only.

  3. 03 CSS

    M03 / The surface

    CSS

    Understand why styles land where they do. Then use the box model, Flexbox, Grid, and media queries to make the same page work at 360 pixels and 1440 pixels.

    • Syntax & selectors
    • Cascade & specificity
    • Box model
    • Flexbox
    • Grid
    • Responsive design
    What this module unlocks

    Learning outcome. Style and lay out pages with CSS — including the box model, Flexbox, Grid, and responsive design for phone and desktop.

    Key question. Why did that rule win?

    Studio exercise

    Rebuild one layout twice: once at phone width, once on desktop. Explain every breakpoint in a single sentence.

  4. 04 JavaScript

    M04 / Behaviour

    JavaScript

    Make the page respond. Use the DOM and events to build interactions, validate forms, and manage state without losing the plot when the interface grows.

    • Variables & types
    • Functions
    • The DOM
    • Events
    • Form validation
    • Interactivity
    • Managing state
    What this module unlocks

    Learning outcome. Add behaviour with JavaScript — the DOM, events, and managed state — in a way another person can follow.

    Key question. What state does this interface need, and where does it live?

    Studio exercise

    Build a form that tells the user what went wrong, in plain language, before they can submit.

  5. 05 Build

    M05 / From exercises to a site

    Project development

    Move from isolated exercises to a real site. Define the idea, map the pages, sketch the wireframes, gather the media, and test the thing like someone else's work.

    • Planning
    • Wireframing
    • Structure & navigation
    • Media
    • Testing
    • Debugging
    What this module unlocks

    Learning outcome. Plan, build, deliver, and defend a complete website of your own design, with navigation that works and content worth reading.

    Key question. What is the smallest site that does this idea justice?

    Studio exercise

    Write a one-sentence brief, draw a five-box sitemap, and save three references you are not copying.

  6. 06 Publishing

    M06 / Out of localhost

    Publishing

    Put the work on the internet, properly. Prepare the files, commit a meaningful history, deploy to a live address, connect a domain, and help people find what you made.

    • Preparing files
    • Git & GitHub
    • Deployment
    • Domains
    • Basic SEO
    What this module unlocks

    Learning outcome. Publish and operate a website: version control, deployment to a live address, and diagnosing faults across layers.

    Key question. When the live site differs from your computer, which layer changed?

    Studio exercise

    Ship a real page, connect a URL, and write a README your future self can follow at 11pm.

  7. 07 Security

    M07 / Trust boundaries

    Web security

    Treat the web as a hostile place for a moment. Learn what HTTPS protects, where passwords should live, and how XSS and CSRF sneak into ordinary-looking pages.

    • HTTPS
    • Secure password handling
    • XSS awareness
    • CSRF awareness
    • Security-first defaults
    What this module unlocks

    Learning outcome. Recognise common web security failures and design safer defaults, even on a site with no backend.

    Key question. What can a visitor control, and where does that input go?

    Studio exercise

    Review three everyday patterns — a login form, a comment box, a settings page — and mark the trust boundary in each.

  8. 08 AI review

    M08 / The central skill

    Working with AI tools

    AI is a fast typist with no context. Learn to specify precisely, question assumptions, verify behaviour, and correct generated code before it reaches users.

    • Specifying
    • Verifying
    • Correcting
    • Reviewing generated code
    • Accountability
    What this module unlocks

    Learning outcome. Judge code you did not write, including code produced by AI tools — for correctness, accessibility, safety, and fit.

    Key question. What would you have to prove before putting your name on this code?

    Studio exercise

    Take an AI-generated feature from prompt to production review. Document what you changed and why.

02 How it works

Read. Make. Review.

The sequence is deliberate. Understanding without making is hollow; making without reviewing is how broken interfaces ship.

01 / READ

See the idea.

Concise explanations and examples connect each concept to the full lesson material and to the web you already use.

02 / MAKE

Build the thing.

Every module ends in a studio task. Nothing is theoretical for long: the work feeds directly into your site.

03 / REVIEW

Judge the result.

Test against the brief, accessibility, and the layers underneath. Ask what works, what is fragile, and what you would change.

03 Keep going

The modules are the map. The project is the territory.

Everything you learn here converges on one brief: a complete, accessible, responsive site at a live address, with a Git history that shows the work developing.
