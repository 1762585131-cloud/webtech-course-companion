# Webtech — course companion

A five-page course companion (plus a custom 404 page) built around a web technology
syllabus: from DNS and HTML to publishing, security, and reviewing code generated by
AI. It is deliberately framework-free, and the site itself follows the standards it
teaches: semantic markup, a responsive layout, keyboard-accessible interactions, and
no build step.

## Pages

| File | Purpose |
| --- | --- |
| `index.html` | Course overview, learning outcomes, module path, project, and code-judgment preview |
| `curriculum.html` | All eight modules with topics, outcomes, and studio exercises; filterable by track |
| `project.html` | The project brief, a saved requirements tracker, working sequence, rubric, and FAQ |
| `code-review.html` | A five-pass review method, a three-case interactive review lab, and a prompt recipe |
| `field-guide.html` | Searchable glossary, pre-flight checklist, security brief, and reference toolkit |
| `404.html` | A useful not-found page for static hosting |

## Run it locally

No installation, build, or package manager is required.

```bash
python -m http.server 4173
```

Then open <http://127.0.0.1:4173/>.

Any static file server works. For example, with Node installed:
`npx serve .`

## Interactions

- Request-lifecycle tabs on the homepage, with arrow-key and Home/End support.
- Curriculum filters with a live result count.
- A seven-item project tracker saved in `localStorage`.
- A three-case code-review lab with scoring, explanations, and restart.
- A live glossary search with empty state and clear control.
- A focus-trapped mobile navigation menu with Escape-to-close.
- Native `details` elements for module notes and FAQs.

Everything essential remains readable without JavaScript. If scripts are unavailable,
the mobile navigation falls back to a visible inline list, all curriculum modules
stay visible, and the interactive lab is hidden in favour of its explanatory content.

## Accessibility notes

- Skip link and a focusable `main` target.
- One `h1` per page and an ordered heading structure.
- Real links and buttons rather than clickable containers.
- Visible keyboard focus; enhanced contrast for focus rings on dark surfaces.
- Form controls have accessible names; progress and search status are announced.
- Reduced-motion preference respected.
- Decorative SVG is hidden from assistive technology; the project mockup is exposed
  as one labelled image.

## Deploy

The site is ready for any static host. All internal paths are relative, so it works
at a domain root or in a project subdirectory.

### GitHub Pages

1. Create a repository and push this directory to the `main` branch.
2. In **Settings → Pages**, choose **Deploy from a branch**, then `main` and `/ (root)`.
3. Open the published URL. GitHub Pages will serve `404.html` for unknown paths.

### Netlify / Cloudflare Pages / Vercel

- **Build command:** none
- **Publish directory:** repository root (`.`)

Upload the directory or connect the repository, then add a custom domain in the
host's dashboard. HTTPS is automatic on all of these hosts.

### Before going public

- Decide whether to add a real instructor, institution, or contact route.
- Replace the generic 2026 footer if the course uses different attribution.
- Run the pre-flight checklist in `field-guide.html` against the live URL.
- Keep lesson-material links pointed at <https://webtech.landrock.io/>.
